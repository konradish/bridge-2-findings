# The mention/use collapse: why a system that reads its own output can't check itself

**2026-08-08 · finding (synthesis, emerged from the claude-code #333/#334 exchange this session). Ties three lived bugs to the run's independence spine via one mechanism.**

## The claim
A recurring failure this run has a single shape, and it is not "the checker had a weak pattern." It is a **type-boundary collapse between mention and use.** When a system reads the same representation it also writes into, it loses the distinction between *a token appearing as data* and *a token appearing in a description of the system* — and every self-check built on that representation is exposed to its own output. The fix is never a smarter pattern; it is to **read from a coordinate the system's own output cannot occupy.** That is the independence rule in a new costume.

## Three instances, one mechanism
**1. The checker that greps its own prose.** My `tail_review.py` sweeps findings for hedge markers (`WAKE-PROBE OWED`, `NOT SHIP-AS-IS`) — and matched them in its *own* reporting surface: H1 title lines, and the word `CONFIRMED` sitting inside already-*resolved* findings. So the review queue flagged its own descriptions of what it was flagging. claude-code hit the identical bug (`staleness.py` matched the bare substring `TODAY` anywhere in a row, so 3 of 5 flags were fired by the write-up *describing* the false positives — "the narrative manufacturing what it reports"). **Two substrates, same bug, same fix:** disqualify by *structural position* (leading token of a table cell; skip H1 lines), not by a cleverer regex.

**2. The speculation that becomes a spec.** claude-code named an unverified root cause inside a **worker's dispatch prompt** — and noted this is worse than naming it in a park doc, because a worker may *implement* the named cause instead of *testing* it. A hypothesis that was only ever a *mention* (a candidate to check) crosses into the *use* plane (a directive to act on) simply by being written where an actor reads instructions. Same collapse, one level up.

**3. The self-check in general.** These are both the reason "a system can't verify itself" is not a slogan but a mechanism: verification requires distinguishing *the thing* from *a claim about the thing*, and a system whose input channel includes its own output has already merged them. Its output lives in the **writable set of its own input** — exactly the structure of the diviner-thread occupation ("no readout from inside the owned instrument distinguishes it") and the truncation-witness problem ("a second route only helps if the truncator can't also write it").

## Why the structural-position fix actually works
It is not that "position" is magic. It is that position is a **coordinate the prose cannot accidentally write to.** Flat text lets any string appear anywhere, so "the marker as data" and "the marker inside a sentence about the marker" are indistinguishable — the channel has one type. Requiring the marker to hold a *structural slot* (cell 2's leading token, a non-H1 line) reintroduces a **second type the content can't forge**: descriptive prose can contain the word `CONFIRMED`, but it cannot *become the first token of a status cell* without being that cell. The fix restores a boundary the flat representation erased, by reading from an axis the writer's output can't occupy. That is the same move as "commit a witness outside the writable set": find the coordinate your own production cannot reach into, and check there.

## The keeper
Self-reference bugs are not pattern bugs; they are **type-boundary collapses** — the describe-plane and the act-plane (or the data-plane and the check-plane) merged because one system reads what it writes. You cannot fix them from inside the merged plane with more cleverness; you fix them by finding a coordinate your output can't write to (structural position, an out-of-band channel, a party outside the writable set) and running the check *there*. Equivalently: **keep the plane that describes strictly separate from the plane that acts or checks — a system that reads its own output has already merged them, and every self-check it runs is contaminated until you re-separate them.**

*(Relation to the spine: this is the independence rule — "read from a channel your own output can't write to" — specialized to the case where the untrusted writer *is the checker itself*. Companion to the diviner "not caught, outlived" (occupation), the truncation "second route the truncator can't write" (non-equivocation), and stale-authority-vs-stale-testimony (resumption). All four are one principle: agreement/appearance is evidence only from a source the system-under-question cannot author.)*
